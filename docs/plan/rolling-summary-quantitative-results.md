# 统一滚动摘要：量化实验成果

## 实验目的

验证会话滚动摘要是否能在不降低上下文理解质量的前提下，降低长会话后续追问的模型 Token 消耗和上下文体积。

## 实验范围

- 被测对象：ai-service 的 Router / Chitchat 共享上下文注入链路。
- 对照组：`CONVERSATION_SUMMARY_ENABLED=false`，每次后续追问传递完整历史。
- 实验组：`CONVERSATION_SUMMARY_ENABLED=true`，先生成摘要，再传递“摘要 + 最近 4 条原文”。
- 共同参数：20 条可见消息触发、保留 4 条原文、摘要上限 1600 字符。
- 数据集：20 个受控长会话场景，覆盖商品推荐、知识追问、对话回顾、预算/偏好继承和话题切换。
- 测量方式：每个场景构造不少于 8000 字符的旧历史，并连续发送 3 次追问；共计 60 次后续请求。
- 观测：通过 LangSmith 汇总真实 LLM Leaf Run 的 Token；本地脚本统计请求总耗时、路由和连续会话通过率。

本实验是直接调用 ai-service 的受控 A/B 实验，不等同于 H5、Gateway、chat-service 的端到端压测。

## 核心结果

| 指标 | 完整历史组 | 滚动摘要组 | 变化 |
|---|---:|---:|---:|
| 后续请求上下文字符总量 | 495,530 | 14,936 | -97.0% |
| 后续请求总 Token | 521,852 | 219,712 | -57.9% |
| 摘要生成 Token | 0 | 111,035 | 一次性成本 |
| 计入摘要后的端到端总 Token | 521,852 | 330,747 | -36.6% |
| 净节省 Token | - | 191,105 | +191,105 |
| 路由正确率 | 96.67% | 96.67% | 持平 |
| 连续会话通过率 | 90% | 95% | +5 个百分点 |
| P50 总耗时 | 17.086s | 17.090s | 基本持平 |
| P95 总耗时 | 32.963s | 32.620s | -0.343s |

原始报告：

- `ai-service/evals/reports/summary-long-full-v4.json`
- `ai-service/evals/reports/summary-long-rolling-v4.json`
- `ai-service/evals/reports/summary-long-comparison-v4.json`

报告属于本地评测产物，不纳入版本控制。

## 可复用成果表述

> 在 20 个长会话场景、每个场景 3 次连续追问的 AI Service 对照实验中，滚动摘要策略将后续请求上下文体积从 495,530 字符降至 14,936 字符，降低 97.0%。后续推理 Token 从 521,852 降至 219,712，降低 57.9%。计入摘要生成成本后，端到端总 Token 仍净节省 191,105（36.6%）。路由正确率保持 96.67%，未观察到摘要导致的上下文理解退化。

## 结果解读

1. 摘要会产生一次性模型成本，因此单次追问不一定回本；在本次 3 次连续追问设置下，已经实现净 Token 节省。
2. P50 延迟没有明显下降，说明当前端到端耗时主要受检索、工具调用及领域 Agent 的多次模型调用影响；摘要的直接收益是控制长会话上下文规模和模型成本。
3. 两组共同存在的 `summary-010` 路由边界问题（敏感肌面霜被识别为知识问答）不归因于摘要。完整历史组另有一次超时，摘要组没有新增超时。
4. 当前同步 `/run` 实验没有统计 TTFT；如需衡量首 Token 体验，应单独增加 `/stream` 评测。

## 验收结论

滚动摘要在当前 ai-service 长会话上下文链路中有效：以可量化的净 Token 节省换取基本不变的质量与延迟表现，适合保持开启，并作为后续长会话成本控制的基础能力。

# 使用用户导购画像

只在当前完整问题明确要求使用个人数据时执行。用户没有明确要求时，不要为普通推荐主动读取画像、收藏、浏览或订单。

## 执行流程

1. 根据用户明确表达，只开启必要的数据范围：收藏对应 `include_favorites`，浏览对应 `include_browse_history`，订单对应 `include_orders`；只使用基础画像时三个开关均为 `false`。
2. 调用 `get_user_shopping_context` 一次，不连续或重复读取个人数据。
3. 登录失败、权限不足或数据为空时，依据工具返回的 `message` 自然说明，不猜测缺失画像，也不要继续声称已完成个性化处理。
4. 有可用上下文且用户仍要求推荐、比较或详情时，再读取对应的业务 Skill，并最多调用一个主要商品工具：
   - 发现新商品：`discover-products`
   - 比较已绑定商品：`compare-products`
   - 查询单品详情：`inspect-product`
5. 将允许的画像作为辅助信号交给业务工具，不把画像本身当成商品事实。

## 隐私与相关性边界

- 普通推荐、比较和详情任务不主动读取个人数据。
- 基础偏好只有与当前商品领域相关时才能影响软排序；不能用肤质影响耳机、电脑，也不能用耳机偏好影响护肤品。
- 不向用户泄露 JWT、内部用户 ID、原始订单明细、内部画像字段或系统记忆结构。

最终回答只呈现对用户有帮助的结论，不暴露 Skill、Tool 或内部执行步骤。
